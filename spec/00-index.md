# loop CLI Specification

`loop` is a Go-based AI coding harness CLI. It repeatedly runs an external coding agent against one Markdown instruction file through CLI-owned planner, coding, QA review, and merge roles, records each iteration, creates validated commits for complete task work, and integrates each iteration into the base branch.

The specification defines what to implement. It does not include source comparisons, benchmark notes, or project commentary.

## Default behavior

- The default agent is `codex`.
- All generated prompts, plans, commit messages, memory files, default skill text, and CLI-owned pull request fallback text use English.
- Runs are fully automated by default. The CLI proceeds without direct user questions or manual user actions; important clarifications go through GitHub Issues.
- Each iteration targets one AI sprint-sized pull request: the largest coherent development goal suitable for an autonomous run while still producing an independently mergeable result.
- The planner writes a dependency-aware task tree for that sprint-level PR. Task nodes are meaningful coding-agent work packets, not layer-only microtasks. Coding agents complete assigned tasks in CLI-created worktrees by creating task-local TODOs, committing each TODO through the CLI, and using `loop task merge` to finish task integration. The QA review agent approves or returns cross-task repair findings. The merge agent owns PR branch rename, PR text, creation, checks, and merge through loop commands, and reports PR check failures as `pr_check_failed`.
- Language and workflow details remain customizable through `.loop/config.yaml`, repository skills, and the user-owned Markdown instruction file.
- The compact skill bootstrap is generated by the Go implementation. User instruction files are task input only and must not be used as a substitute for system-level loop behavior.

## Primary command shape

```bash
loop init
loop run path/to/instruction.md --goal "The target behavior is implemented and verified"
```

The instruction Markdown is user-authored task input and is read at every iteration through the `instruction` artifact. The CLI injects a compact, non-user-editable skill bootstrap from code. The optional goal is evaluated by planner and review handoffs through `goal_complete`; it can stop the run only after successful integration.
